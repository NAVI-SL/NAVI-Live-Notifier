## Limits and abuse controls

Existing web lookup admission: ten resolves per actor/minute. Better Auth sign-in rules and prepared proxy limits remain; real proxy enforcement not yet verified. Explicit tests use persisted per-guild cooldown/admission and idempotent request IDs. Automatic delivery uses persistent session/guild/channel uniqueness, current destination permission, deterministic enforced nonce, at most five safe attempts, durable Retry-After, conservative uncertain handling and max 50 delivery claims per tick. No arbitrary role/everyone mention from templates; everyone only explicit saved administrator choice with current channel permission, never preview/test everyone pings.

A source subscription is unique per guild/provider identity; existing global source cap bounds unique sources, not a fair-share quota per tenant. Sharing a source across guilds saves detection calls but multiplies sends and fresh bot permission reads. At five guilds × ten sources the candidate workload is 50 destinations, **not measured capacity**. No rate-limit bypass or automatic increase is introduced. Follow returned Discord buckets/global limits and retry timing; do not load-test production APIs. [Official Discord rate limits](https://docs.discord.com/developers/topics/rate-limits).
