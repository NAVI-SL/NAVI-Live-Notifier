## Security findings and limitations

**Credentials/privacy: PASS within automated scan coverage.** The copy contains only example environment files. Exact comparison against eight distinct configured credential candidates, plus common Discord/Google/GitHub/AWS token, Discord webhook and private-key signatures, found no remaining matches. Real environment files and Git history are absent. Synthetic test credentials are intentionally retained so regression tests are reproducible. Automated pattern scans cannot guarantee detection of every unknown secret; review staged files before any upload. Git ignores do not protect manual file uploads or previously tracked files.

**Dependencies: known moderate findings remain.** Both npm audit and npm audit --omit=dev return exit 1 with **four moderate, zero high and zero critical** findings. The chain is drizzle-kit → @esbuild-kit/esm-loader → @esbuild-kit/core-utils → esbuild (GHSA-67mh-4wv8-2f99). Although used for tooling, this chain is also present in the production dependency tree through Better Auth's Drizzle peer dependency. Do not describe it as absent from production or solved by --omit=dev. No vulnerable esbuild serve endpoint was enabled in this task; that does not eliminate the dependency finding. The offered automatic fix is a semver-major downgrade to drizzle-kit 0.18.1 and was not applied because this task preserves the working application/lockfile. Track compatible remediation and assess runtime exposure before deployment; do not run audit fix --force blindly.

**Deployment blockers remain.** No approved OCI host, domain/TLS, public callbacks, production secret provisioning, host capacity measurement, durable off-host encrypted backup/restore, operational alert verification or newly observed controlled livestream receipts have been established by this task. Privacy/Terms/operator/support/data-deletion placeholders still require owner/legal review before public use. No legal compliance or free hosting availability is asserted.

## Linux ARM64 and Oracle Cloud

The actual application image built and ran offline smoke checks as linux/arm64, covering target-architecture Next.js compilation and runtime imports. PostgreSQL/Redis/Nginx ARM64 manifests were verified, but those three services were not exercised on ARM64 in this task. Database integration ran against a local Docker PostgreSQL fixture, not an Oracle server. This is meaningful ARM64 compatibility evidence, not a native Ampere performance, capacity, network or full-deployment certification.

Official references reviewed: [Oracle Arm-based Compute](https://docs.oracle.com/en-us/iaas/Content/Compute/References/arm.htm) and [Docker multi-platform builds](https://docs.docker.com/build/building/multi-platform/). Build and install on the chosen architecture; never upload Windows dependencies/build outputs to Linux. Review the deployment guide and production checklist, preserve private broker/database networking, supply independent secrets/TLS and test restore/health/recovery before any approved deployment. No purchases, DNS or public installation changes are authorized by this report.
