## Completed configuration

- Multi-stage Node 24 Docker image with lockfile install, native full production build, runtime install and nonroot service user. Secrets/local builds are excluded from the context. Base tags need immutable digest resolution and image scanning before release.
- Separate services with init/signal forwarding, read-only application root/temp cache, log rotation, 45-second stop grace and `unless-stopped` policy. Health failure itself does not trigger a restart.
- Existing loopback broker retained; edge is the only published entry point, loopback-bound for review. Nginx TLS/body/time/rate/Host controls and exact supported callback routing supplied. TLS certificate provisioning/renewal is manual; no DNS or public bind was enabled.
- Runtime `NAVI_ENV_FILE` selection permits one explicitly mounted service secret without loading other services' values; missing explicit files fail closed with safe errors. Production launcher rejects missing bot credentials, disabled worker monitoring and invalid web auth configuration.
- Explicit migration tools job with advisory serialization, no auto-reset; nonsuperuser runtime role grant script supplied and tested in isolated embedded PostgreSQL. Intended production roles/database were not created on any real server.
- Private container probes: web liveness plus auth-schema access, bot REST identity, worker required-platform readiness. Structured app logs retained; status-only edge logs and size rotation configured. External error/alert provider remains unselected.
- Backup/restore, secrets/TLS/DNS, restart/recovery, hosting costs and public release gates documented in the accompanying guide/checklist. No backup, production credential or certificate was fabricated.
