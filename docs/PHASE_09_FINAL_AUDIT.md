## Major issues and release gates

### M01 — External database/persistence/recovery acceptance unavailable

**Major acceptance/operations gap, reproduced infrastructure blocker.** Actual PostgreSQL returns ECONNREFUSED and `test:postgres` exits 1. No current schema/migration journal, 0006 `mention_everyone` column, real runtime-role permissions, persistent settings restart, independent-connection claim/lock behavior or backup restore was verified. The latest recorded real application migration remains unresolved; neither pending nor applied state can be freshly inspected today. PGlite success cannot close this gate.

**Required correction/evidence:** restore the intended local service without resetting volumes; privately verify the target; review/apply additive migrations through 0006 as required; pass `db:check` and `test:postgres`; validate nonsuperuser roles, committed settings/ledger survival after real restart and restore into a separate test database. Reconcile sent/deduplication state before monitoring after an old restore. Do not treat successful compilation as schema compatibility.

### M02 — Full real user journey and received notifications unverified

**Major acceptance gap.** Monitoring is disabled and the worker is not listening. No fresh real OAuth/logout/install/status/registration/settings journey, labelled received sample, controlled YouTube or Kick start, actual two-guild delivery, repeat/reconnect duplicate check or worker-with-web-off observation exists for Phase 9. Read-only APIs and bot health succeed but demonstrate none of these side effects.

**Required correction/evidence:** identify approved test guilds/channels, manager/non-manager accounts and controllable broadcaster accounts; complete the Phase 9 closure sequence with canonical origin and baseline established before the start. Record actual timestamps, public stream identities, redacted delivery state/logs and received-message counts/screenshots for each platform/destination. Preserve private app/allowlist/default-off mass mentions. Inspect Discord before any new click following uncertainty; do not blindly resend.

### M03 — Runtime/deployment and operational recovery not executed

**Major acceptance/operations gap.** Docker Linux engine unavailable; no validated image, Node 24 runtime, actual mounted secret ACLs, Nginx/TLS/path/rate behavior, healthy service startup, signal/restart recovery, volume/restore drill or unattended alert path. Config/model checks cannot establish these. Shared edge namespace replacement requires coordinated app recreation; Gateway ownership does not span Windows and the Docker VM. Logs/probes alone do not deliver alerts or renew certificates.

**Required correction/evidence:** execute the documented isolated local deployment acceptance after local Docker/secrets/certificates are ready, with one Gateway owner; test shutdown/restart, web-off monitoring, unavailable dependencies, backup restore and appropriate operator alert handling. A personal local beta needs a working measured operating profile; public hosting/domain purchases are not necessary to resume local tests. Unattended/public service additionally requires approved hosting, trusted HTTPS/callbacks, encrypted offsite backup/renewal/alert operations. No public deployment or infrastructure approval is inferred here.

### M04 — YouTube coverage/Premiere boundary lacks measured acceptance

**Major product feasibility/acceptance gap.** Candidate-only detection is not a guarantee of detecting every registered channel's start. Google's documented feed events concern uploads/title/description changes; they do not guarantee universal go-live discovery. No measured scheduled/unscheduled/long-scheduled/short stream discovery, Premiere classification or latency/quota acceptance was supplied. Styling and successful API authentication do not resolve this.

**Required correction/evidence:** run controlled cases, including ordinary videos/Premieres and already-live suppression; record misses as well as latency and quota. Explicitly agree/disclose the beta's supported discovery/Premiere behavior before GO. Do not invent endpoints, scrape or evade quota to hide the gap.

## Minor issues and residual risks

### N01 — Four moderate dependency advisories

Fresh audit still lists `@esbuild-kit/core-utils`, `@esbuild-kit/esm-loader`, `drizzle-kit`, `esbuild`; no high/critical findings. npm offers a breaking Drizzle Kit 0.18.1 change. Production-only classification includes this tooling chain, so simply omitting dev dependencies is not evidence that it disappears.

**Correction:** verify a compatible resolution or record owner acceptance/exposure controls; do not force a downgrade. Scan the actual Linux image when M03 is unblocked. No affected tooling server is intentionally exposed, but that is mitigation rather than remediation.

### N02 — Production hardening/readiness scope remains limited

Floating base/release tags are not immutable image pins; no image scan/history inspection. CSP is partial. Web private health checks auth-schema access rather than complete migration currency, bot health checks REST rather than Gateway acknowledgment, and shared-host ownership cannot ensure a distributed singleton. These are disclosed limits, not demonstrated exploits.

**Correction:** pin/scan the approved release artifact and verify runtime secrets and networking; retain worker schema checks and Gateway lifecycle observation in acceptance. Review CSP and host/abuse controls before broader exposure. Do not relabel narrow health responses as comprehensive end-to-end health.

### N03 — Evidence reproducibility and historical status need care

The Phase 9 JSON is a manually assembled sanitized summary, not a retained complete runner transcript; temporary browser/HTTP probes were removed. It lacks an immutable source revision/hash manifest tying all observations to one release artifact. Inspection corroborates its limited claims, but it cannot reproduce the entire authenticated journey or establish an unobserved successful send. Older planning paragraphs still contain superseded phase/status/architecture proposals despite current pointers.

**Correction:** preserve sanitized runner summaries with timestamps, relevant source/lockfile/image identifiers and approved-target receipt evidence for final sign-off. Keep browser test steps/environment and failures reproducible without retaining OAuth material. Treat dated audits and original proposals as history; use the current roadmap/contracts. No rewrite of historical audit verdicts is warranted.

## Final decision and conditions for GO

**NO-GO for private beta; continued controlled local testing is appropriate.** The application has a reproducible passing automated baseline, secure-looking reviewed boundaries and functioning read-only API credentials. That evidence is materially narrower than the product promise.

Minimum sign-off requires:

1. Working external PostgreSQL with reviewed current migrations/roles, restart persistence, concurrency and isolated restore evidence (M01).
2. Fresh complete real browser journey plus observed automatic YouTube and Kick alerts in approved destinations, two-server isolation/fan-out, no duplicate on repeats/restart and continued worker operation without web/browser (M02).
3. Executed, documented runtime/security/recovery checks for the intended local beta profile; complete public deployment gates separately if public hosting is requested (M03).
4. Measured and accepted YouTube discovery/Premiere/quota limitations, and recorded disposition of residual dependency/hardening risks (M04/N01–N03).
5. Explicit owner release sign-off against those updated results. **No approver, release date or acceptance of risks is fabricated.**

Real-world livestream tests: **YouTube BLOCKED; Kick BLOCKED. Actual Discord notification receipt: BLOCKED.** These results remain unchanged by successful simulations, historical screenshots, read-only authentication or the phrase “Phase 9 completed.” No Phase 10 started.
