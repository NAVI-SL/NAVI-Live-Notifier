## Distinct request scopes

| Request                                                           | Current capability / authorization boundary                                                                                                                                                                                                    |
| ----------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Stop future alerts                                                | Authorized manager disables notification settings/subscription. In-flight requests cannot be recalled.                                                                                                                                         |
| Remove one guild subscription                                     | Existing authorized Remove operation deletes that subscription/settings. Shared source remains if another guild needs it. Some historical delivery guild/channel IDs may remain with shared sessions.                                          |
| Delete NAVI account                                               | Manual operator workflow; no browser account-deletion endpoint currently exposed. Delete only verified user's auth records/sessions/credentials, not unrelated guild settings. Subscriptions do not record creator ownership as an account FK. |
| Delete an entire guild's retained data                            | Verify current guild owner/manager authority and scope. Separate from account deletion; review settings/subscriptions/test attempts and historical guild delivery rows.                                                                        |
| Broadcaster public-data request                                   | Verify the request and applicable platform/user rights; distinguish public metadata from Discord-manager data. Shared-source effects require review; do not disclose which other servers subscribed.                                           |
| Delete source platform account/broadcast or prior Discord message | NAVI data deletion does not delete YouTube/Kick accounts/content. Discord message deletion uses platform/channel controls; automatic message IDs are not stored, so no automated historical erasure is promised.                               |

## Procedure and evidence

1. **Receive and minimize.** Record request ID/time, scope and appropriate verified actor using a protected case record. Ask for public account/guild identifiers only as needed. Never request OAuth codes, cookies, bot/API tokens, passwords or identity documents through an unapproved support channel. Support contact and case-store retention/ACLs require owner approval.
2. **Verify authority.** Use existing authenticated identity and fresh Discord guild authorization when available. If access was revoked or provider unavailable, use a reviewed alternative verification process; do not reject a legitimate personal-data request merely because the user cannot log in. Avoid accepting arbitrary emailed guild IDs as authority. Escalation owner/contact **[TO BE CONFIRMED]**.
3. **Set deadline and contain.** Assess applicable platform/legal obligations per request, record owner/deadline and promptly stop relevant processing. Proposed operator target: acknowledge within two working days and complete applicable data deletion as soon as possible, within seven calendar days where the YouTube requested-user-data provision applies. These are preparation targets, not verified public SLA. Current [YouTube Developer Policies III.E.4/5](https://developers.google.com/youtube/terms/developer-policies) must be applied to actual categories; 30-day refresh is not an excuse to defer a seven-day request.
4. **Plan exact records.** Privately map tables/relationships and shared-source dependencies before mutation. Capture only counts/opaque request references, not copies of credentials or stream payloads. Preserve necessary uncertainty evidence with justified bounded retention; do not claim hashes are automatically nonpersonal.
5. **Execute deliberately.** Use existing authorized subscription removal for its supported scope. Manual account/guild cleanup requires reviewed parameterized operator queries in a transaction against the privately verified target, least privilege and affected-row checks. Pause the actual monitoring owner during any ledger/source purge that could permit re-notification. Do not delete other guilds' routes or bulk-reset deliveries. This document runs no SQL or deletion and does not create a new admin API.
6. **Invalidate active copies.** Account deletion must revoke all NAVI sessions and remove auth account credentials through the reviewed auth-user cascade. Assess provider revocation using supported procedures if appropriate; logout alone is insufficient. Handle process caches/in-flight work and provider subscription ownership. Do not rotate the shared auth encryption key as a deletion mechanism for one person.
7. **Verify and propagate.** Check scoped row absence/counts, other guild isolation, shared identity retention only where needed, session denial and stopped eligible sends. Verify logs/backups/exports below; repeat checks after controlled restart. Record sanitized counts and completion date, communicate exceptions and what was not deleted (e.g. platform content/messages).

## Storage map and retention gaps

| Store                                                            | Required review/action                                                                                                                                                                                                                                                                                  |
| ---------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `auth_user`, `auth_session`, `auth_account`                      | User deletion cascades sessions/accounts. OAuth verification entries lack a direct user FK; inspect only request-bound state where identifiable, otherwise enforce short expiry cleanup without dumping codes.                                                                                          |
| `streamer_subscriptions`, `notification_settings`, test attempts | Guild/subscription scope. Settings cascade on subscription removal; test attempts and historic guild data need explicit verified cleanup review.                                                                                                                                                        |
| `provider_channels`, monitoring source/session rows              | Source shared across guilds; delete automatically when last subscription removed through current repository. Removing a guild alone must not destroy another guild's source.                                                                                                                            |
| `live_deliveries`                                                | Contains guild/channel/subscription identifiers and outcomes without subscription FK cascade. Explicit guild/historical cleanup may be necessary while source remains shared. Purge with replay/uncertainty containment, not while continuing uncontrolled sends.                                       |
| Source candidate IDs, session hashes, receipt/test records       | Worker clears session payload after 29 days and receipt hashes after seven days; candidate IDs/session hashes/outcomes can persist longer. Decide necessary retention and test expiry/deletion, including upstream cached references. Current cleanup alone does not close provider-policy obligations. |
| Process caches/logs/case records                                 | Short cache TTL is not deletion verification. Clear/restart reviewed processes safely when needed; define bounded protected log/case retention and incident exceptions. Avoid reintroducing personal data in deletion evidence.                                                                         |
| Backups                                                          | **[BACKUP_RETENTION_AND_DELETION_RULE — REQUIRED]**. An archive outside active SQL still contains data. Determine deletion versus restricted expiring backup handling under applicable obligations; obtain policy review rather than assuming exemption.                                                |

`npm run db:prune-streamers` performs expiry cleanup, **not a general account/guild erasure command**. Normal worker cleanup requires a running worker; schedule reviewed maintenance even when apps stop. Do not run a pruning/deletion command merely to test this draft against application data.

## Restore and release acceptance

Maintain minimal protected deletion exclusions with approved retention/access until affected backups expire, if legally/platform appropriate. Before resuming a restored database, reapply verified exclusions and reconcile sends since its timestamp; never resurrect deleted accounts or replay old notifications. A restored old ledger can lose deduplication evidence, so remain paused until resolved. Schedule/retention and actual restore implementation remain open.

Test in an isolated DB: account deletion invalidates all sessions; guild A deletion leaves B unchanged; shared source survives A removal and is removed after last subscription; historical deliveries/caches are handled; cleanup works with apps off; restore re-applies exclusions without replay. Current tests cover SQL cascades/retention/isolation in parts, **not this complete manual process or backup deletion**. Do not mark the public Privacy Policy final until request intake, authority checks, categories/deadlines, actual erasure/restore and operator evidence are validated.
